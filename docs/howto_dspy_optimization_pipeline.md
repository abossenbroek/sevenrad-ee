# How to Run the DSPy Optimization Pipeline

**Documentation Type:** How-to Guide
**Purpose:** Step-by-step instructions for executing the complete DSPy greenhouse detection optimization pipeline
**Target Audience:** Developers and researchers with basic Python and DSPy knowledge

---

## Quick Start

### 1. Launch the Marimo Notebook

```bash
uv run marimo edit notebooks/dspy_optimization_pipeline.py
```

This opens an interactive web interface in your browser (typically `http://localhost:2718`).

### 2. Execute Sections Sequentially

The pipeline consists of 10 independent sections. Execute each section top-to-bottom by clicking the **Run** button or pressing `Shift+Enter`.

**Critical:** Do not skip sections - each depends on state saved by previous sections.

---

## Prerequisites

### Required Setup

Before starting, ensure you have:

1. **API Keys Configured** (in `.env` file):
   ```env
   GEMINI_API_KEY=your_gemini_api_key
   PERPLEXITY_API_KEY=your_perplexity_api_key
   ```

2. **DSPy Installation** (from GitHub):
   ```bash
   uv pip install "git+https://github.com/stanfordnlp/dspy.git"
   ```

3. **Marimo Installation**:
   ```bash
   uv pip install "marimo~=0.9.0"
   ```

4. **Existing Research Data** (optional):
   - 19 research JSON files in `data/research/`
   - Generated by `batch_company_research.py`

## Section-by-Section Guide

### Section 1: Setup & Environment Configuration
**Duration:** 1-2 minutes
**Purpose:** Verify API keys, create directories, configure DSPy

**Steps:**
1. Run the cell
2. Check the status table - all items should show ✅
3. If any ❌ appear:
   - Add missing API keys to `.env`
   - Restart the notebook
4. When all checks pass, proceed to Section 2

**Troubleshooting:**
- **"GEMINI_API_KEY missing"** → Add `GEMINI_API_KEY=your_key` to `.env` file
- **"DSPy import error"** → Run `uv pip install "git+https://github.com/stanfordnlp/dspy.git"`

---

### Section 2: Re-classify Existing 19 Companies
**Duration:** 10-15 minutes
**Purpose:** Re-run evidence classification with fixed LLM-based classifier

**Steps:**
1. Run the cell - it processes all files in `data/research/`
2. Review the comparison table:
   - **Old** column: Previous (buggy) classification
   - **New** column: Fixed LLM-based classification
   - **Changed** column: Highlights differences
3. Verify: 0% false positives on known negatives (should show ✅)
4. Proceed to Section 3

**Expected Results:**
- 6 known negatives: NEGATIVE/NEUTRAL/AMBIGUOUS (not POSITIVE)
- 13 positives: POSITIVE
- Changed classifications: ~6 companies

**Troubleshooting:**
- **"No research files found"** → Run `batch_company_research.py` first
- **"False positives detected"** → Evidence classifier may need debugging

---

### Section 3: Data Expansion - Company Discovery
**Duration:** 30-60 minutes (manual work)
**Purpose:** Identify 21-31 new companies to reach 40-50 total examples

**Steps:**
1. Run the cell to see current dataset status
2. Review the **Discovery Strategy** table for search query ideas
3. Use the **company entry form:**
   - Enter company name (e.g., "Kwekerij Example B.V.")
   - Enter location (e.g., "Naaldwijk")
   - Select expected label (POSITIVE/NEGATIVE/UNKNOWN)
   - Click **Add to Queue**
4. Repeat until you have ~21-31 companies in queue
5. Click **Save Queue & Proceed to Section 4**

**Discovery Resources:**
- **Trade Media:** groentennieuws.nl, floraldaily.nl, agf.nl
- **Supplier Sites:** signify.com/nl-nl, hortilux.com
- **Negative Search:** Google "onbelichte teelt" + crop type

**Example Companies to Add:**
- Positive: Rose growers, tomato growers (often use LED)
- Negative: Organic growers, summer-only crops, explicitly "onbelichte teelt"

### Section 4: Data Expansion - Batch Research Execution
**Duration:** 20-30 minutes
**Purpose:** Run automated 3-query Perplexity strategy on queued companies

**Steps:**
1. Run the cell - it loads the queue from Section 3
2. Watch the progress bar as it researches each company
3. Review the **results table:**
   - Category: Auto-suggested classification
   - Confidence: Classifier confidence score
   - Dutch Terms: Count of Dutch horticultural terms found
   - Evidence: Positive/negative evidence counts
4. Proceed to Section 5 for manual validation

**Expected Output:**
- New JSON files in `data/research/` (one per company)
- Summary statistics (positive/negative/needs review counts)

**Troubleshooting:**
- **"Perplexity timeout"** → Retry individual companies or increase timeout
- **"No queue found"** → Complete Section 3 first

### Section 5: HITL Validation - Evidence Review
**Duration:** 1-2 hours (manual review)
**Purpose:** Human-in-the-loop review of all auto-categorized companies

**Steps:**
1. Run the cell to load all research files (40-50 companies)
2. For each company in the interactive panel:
   - **Click through to evidence URLs** - verify sources are legitimate
   - **Review evidence quality:**
     * 🥇 Tier-2: Company websites, supplier case studies, job postings (HIGH QUALITY)
     * 🥈 Tier-1: Dutch trade media (MEDIUM QUALITY)
     * 🥉 Tier-0.5: General web (LOW QUALITY)
   - **Make decision:**
     * ✅ POSITIVE - Company uses grow lights (assimilatiebelichting)
     * ❌ NEGATIVE - Company explicitly does NOT use grow lights
     * ⚠️ NEEDS_MORE_RESEARCH - Unclear/contradictory evidence
   - **Add notes** (optional) explaining your reasoning
3. Track progress bar - complete all 40-50 reviews
4. Review quality metrics dashboard:
   - ⚠️ If <80% tier-2 evidence → consider finding more high-quality sources
   - ⚠️ If <70% Dutch sources → prioritize Dutch-language research
5. Click **Validation Complete - Proceed to Section 6**

**Quality Criteria:**
- **Accept POSITIVE if:**
  - ≥1 tier-2 source explicitly mentions assimilatiebelichting/LED/SON-T
  - OR ≥2 tier-1 sources with consistent information
- **Accept NEGATIVE if:**
  - Explicit mention of "onbelichte teelt" or "zonder kunstlicht"
  - OR strong absence of any lighting evidence
- **Mark NEEDS_MORE_RESEARCH if:**
  - Only general web sources
  - Contradictory evidence
  - Unclear company identity

### Section 7: GEPA Optimizer Configuration
**Duration:** 2 minutes
**Purpose:** Configure teacher model, optimizer parameters, and metric

**Steps:**
1. Run the cell to display configuration options
2. **Select teacher model:** (default: Gemini 2.5 Pro)
   - ● Gemini 2.5 Pro - Best value for Dutch (~$1.25/1M tokens)
   - ○ GPT-5 Pro - Highest quality (more expensive)
   - ○ GPT-4 Turbo - Reliable baseline
3. **Adjust GEPA parameters** (sliders):
   - Generations: 10-20 (default: 15) - more = better but slower
   - Population: 5-12 (default: 8) - Pareto frontier size
   - Mutation prob: 0.3-0.7 (default: 0.5) - exploration vs exploitation
   - CV folds: 3-7 (default: 5) - more = more reliable but slower
4. Review the metric configuration (Dutch-aware hierarchical F1)
5. Review cost & time estimates
6. Click **Start Optimization - Proceed to Section 8**

**Recommended Settings:**
- **Quick test:** 10 generations, 5 population, 3 folds (~1 hour)
- **Production:** 15 generations, 8 population, 5 folds (~3 hours)
- **Thorough:** 20 generations, 12 population, 7 folds (~6 hours)

### Section 8: Run GEPA Optimization
**Duration:** 2-4 hours (long-running)
**Purpose:** Execute GEPA optimization with live progress tracking

**Steps:**
1. Run the cell - this is a long-running process
2. Monitor live progress:
   - **Progress bar:** Generation X/15
   - **Metrics table:** Best F1 score updates per generation
   - **Reflection log:** GEPA feedback messages (scroll to see)
3. **Do not close the browser** - the process runs in the notebook
4. When complete:
   - Review the final best F1 score
   - Examine the **results visualizations:**
     * Line chart: F1 evolution
     * Pareto frontier plot
   - Compare **before/after prompts** (should show improvements)
5. Optimized model auto-saved to `results/optimized_program.pkl`
6. Click **Optimization Complete - Proceed to Section 9**

**Expected Results:**
- F1 score improvement: 62% → 85-95%
- Better prompts with Dutch-specific guidance
- Optimization log showing reflection-based improvements

**Troubleshooting:**
- **"Process hanging"** → Check Gemini API rate limits
- **"Out of memory"** → Reduce population size or restart notebook
- **"Low F1 score"** → May need more/better training data

### Section 9: Repeated Nested Cross-Validation
**Duration:** 1-2 hours (50 runs)
**Purpose:** Robust evaluation with 10-repeat 5-fold CV

**Steps:**
1. Run the cell to start cross-validation
2. Monitor progress: Fold X/50 (10 repeats × 5 folds)
3. Watch **running statistics** update:
   - Mean Val F1 (should stabilize around final value)
   - Std Val F1 (lower = more stable)
   - Overfitting gap (target: <10%)
4. When complete, review **visualizations:**
   - Box plot: F1 distribution across 50 folds
   - Line chart: Train vs Val F1 (overfitting indicator)
   - Histogram: Score distribution
5. Review **statistical summary:**
   - 🟢 Good generalization: Gap <10%
   - 🟡 Moderate overfitting: Gap 10-15%
   - 🔴 Severe overfitting: Gap >15%
6. Results auto-saved to `results/cv_results.csv`
7. Click **CV Complete - Proceed to Section 10**

**Success Criteria:**
- Mean F1 ≥ 95%
- Std F1 ≤ 3%
- Overfitting gap < 10%

**Troubleshooting:**
- **"High variance (std >5%)"** → Need more training data
- **"Severe overfitting (gap >15%)"** → Model memorizing training data, need more examples or regularization

## Common Issues

### API Rate Limits
**Problem:** "Perplexity API rate limit exceeded"
**Solution:**
- Wait 60 seconds and retry
- Reduce batch size in Section 4
- Use caching to avoid redundant calls

### Memory Issues
**Problem:** "Out of memory during optimization"
**Solution:**
- Reduce population size (8 → 5)
- Reduce number of folds (5 → 3)
- Restart notebook and re-run

### Low Performance
**Problem:** "F1 score < 90% after optimization"
**Solution:**
- Check data quality in Section 5 (need more tier-2 evidence)
- Add more training examples (expand to 60-65)
- Try longer optimization (20 generations)

### Classification Errors
**Problem:** "Known negatives still classified as POSITIVE"
**Solution:**
- Evidence classifier bug - check `evidence_classifier.py`
- May need more Dutch negation examples in prompts
- Manually review evidence for those companies

## Advanced Usage

### Resuming from Checkpoints

Each section saves state to `cache/` and `data/`. If the notebook crashes:

1. Restart the notebook: `uv run marimo edit notebooks/dspy_optimization_pipeline.py`
2. Re-run **only Section 1** (setup)
3. Skip to the last incomplete section
4. State is loaded automatically from saved files

### Customizing Parameters

**Dataset Size:**
- Minimum: 30 examples (may have high variance)
- Recommended: 40-50 examples
- Optimal: 60-65 examples

**Optimization Duration:**
- Quick test: 10 gen, 1-2 hours
- Production: 15 gen, 2-4 hours
- Thorough: 20 gen, 4-6 hours

**Cross-Validation:**
- Fast: 5 repeats × 3 folds = 15 runs (~30 min)
- Recommended: 10 repeats × 5 folds = 50 runs (~1-2 hours)
- Thorough: 15 repeats × 7 folds = 105 runs (~3-4 hours)
